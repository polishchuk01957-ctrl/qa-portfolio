# API-002 - Негативне тестування Swagger Petstore

**Проєкт:** Swagger Petstore  
**Тип:** API Testing, Negative Testing  
**Інструмент:** Postman

## Мета перевірки

Перевірити, як API обробляє некоректні вхідні дані та чи відповідають HTTP-статуси фактичним результатам запитів

## 1. Перевірка з некоректним ID

**Метод:** PUT

**URL:** https://petstore.swagger.io/v2/pet

**Тестові дані:**

```json
{
  "id": "abc",
  "name": "Chubaka",
  "status": "sold"
}
```

**Очікуваний результат:** API повертає помилку клієнтського запиту, наприклад HTTP 400 або 422

**Фактичний результат:** отримано HTTP 500 Internal Server Error. У відповіді повернулося повідомлення `something bad happened`

**Статус:** Failed

## 2. Перевірка з відсутнім ID

**Метод:** PUT

**URL:** https://petstore.swagger.io/v2/pet

**Тестові дані:**

```json
{
  "id": null,
  "name": "Chubaka",
  "status": "sold"
}
```

**Очікуваний результат:** API коректно обробляє відсутній ID відповідно до специфікації

**Фактичний результат:** отримано HTTP 200 OK. Сервер повернув запис із призначеним ID

**Статус:** Потребує додаткової перевірки

## 3. Перевірка неправильного типу status

**Метод:** PUT

**URL:** https://petstore.swagger.io/v2/pet

**Тестові дані:**

```json
{
  "id": 0,
  "name": "Chubaka",
  "status": 123
}
```

**Очікуваний результат:** API відхиляє некоректний тип даних або повертає помилку валідації

**Фактичний результат:** отримано HTTP 200 OK. У відповіді поле `status` містило рядкове значення `"123"`

**Статус:** Потребує додаткової перевірки

## Висновок

Під час негативного тестування виявлено нестандартну обробку некоректних даних. Запит із рядковим значенням ID повернув HTTP 500, а запити з `null` та числовим значенням `status` були прийняті сервером

Для остаточного висновку потрібно перевірити поведінку API відповідно до специфікації та повторити запити. Сам по собі неочікуваний результат ще не підтверджує наявність дефекту
